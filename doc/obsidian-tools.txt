QUICK START                                        *obsidian-tools-quickstart*

Requires Neovim 0.11+. markdown-tools.nvim is required. Open Markdown inside
an existing .obsidian vault for auto-detection, or configure explicit
workspaces.

>lua
    require("obsidian_tools").setup({ auto_detect = true })
<

The example above selects a small working setup. Full defaults, options and
feature contracts are documented in this reference. Public installation and
package-manager examples are in README.md.

LUA API                                                   *obsidian-tools-api*

require("obsidian_tools") exposes:
  setup(opts?)              Validate fresh defaults and attach vault buffers.
  dispose()                 Remove owned commands and invalidate queued work.
  workspace(file?)          Return the selected workspace, or nil.
  info()                    Return workspace and copied options without scanning.
  quick_switch(query?)     Select a note by title/path.
  new(title?)               Create a note; omitted title opens an input prompt.
  daily(date?)              Open/create the daily note, optionally YYYY-MM-DD.
  dailies()                 Select an existing daily note.
  search(query?)            Search note contents, prompting when omitted.
  tags(tag?)                Select notes for a tag, or select a tag first.
  backlinks()               Select resolved links to the current note.
  follow_link(link?, source?)  Delegate a shared Markdown link.
  link()                    Select a note and insert a wiki link.
  template(name?)           Insert a named template or open its picker.
  plan_rename(destination)  Return a read-only rename proposal; write nothing.
  apply_rename(plan)        Apply a validated plan; return file/reference counts.
  rename(destination?)      Prompt or rename/move the current note.
  refresh()                 Refresh the index and report note/read-error counts.
  menu()                    Open the action menu.
  command(args)             Dispatch the same action text as :ObsidianTools.

Most workflow actions require the current Markdown source to belong to a vault.
They can schedule indexing or prompts; an immediate return is not completion of
all user interaction. Stale source-buffer contexts and disposed generations do
not perform queued edits. follow_link returns nil for an unhandled external or
out-of-vault link, true for accepted work, or false and an error for no link.
apply_rename validates snapshots and returns {files, references}; validation and
write failures are errors. See the rename contract for rollback limits.

BEHAVIOR AND EXAMPLES         *obsidian-tools-reference-behavior-and-examples*

Vault workflows for Neovim 0.11+, with markdown-tools.nvim as the shared
Markdown syntax/editing layer. This plugin owns note identity, vault indexes
and link resolution. Physical keys, picker UI, completion UI, images and
rendering stay with your configuration and existing plugins.

>lua
    require('obsidian_tools').setup({
      workspaces = { { name = 'Research', path = '~/Research/Obsidian_Workspace' } },
      notes_subdir = 'notes',
      daily_notes = {
        folder = 'dailies',
        date_format = '%Y-%m-%d',
        alias_format = '%B %-d, %Y',
        template = 'daily-note.md',
        default_tags = { 'daily-notes' },
      },
      templates = { folder = 'templates', date_format = '%Y-%m-%d', time_format = '%H:%M' },
      -- note_id = function(title, ctx) return ... end,
    })
<

Install both plugins on `runtimepath` before setup. Multiple workspaces select
the longest matching path. `auto_detect = true` optionally discovers an
ancestor `.obsidian/`; the default is false. No global mappings, cwd changes
or editor options are installed. Commands attach only to ordinary Markdown
buffers inside the selected vaults. Setup and buffer entry do not scan notes.

COMMANDS                                   *obsidian-tools-reference-commands*

`:ObsidianTools` opens a searchable action menu through `vim.ui.select`. Use
`:ObsidianTools {action} [argument]` for direct actions:

  Action — Behavior
  `quick_switch [query]` — Select notes by title and vault-relative path.
  `new [title]` — Create a note using the configured ID function, or
      timestamp/title by default. Existing filenames are retained and
      collisions get a suffix.
  `daily [YYYY-MM-DD]` — Open/create a daily note, applying its optional
      template.
  `dailies` — Select daily notes, newest filename first.
  `search [query]` — Literal, case-insensitive content search, with line
      navigation.
  `tags [tag]` — Select a tag, then a matching note.
  `backlinks` — Select resolved references to the current note.
  `follow_link` — Follow the link under the cursor, selecting ambiguous note
      matches.
  `link` — Select a note and insert a vault-relative wiki link.
  `template [name]` — Insert a rendered template before the cursor as one undo
      step.
  `rename [path]` — Rename/move the current note to a vault-relative path and
      update supported links.
  `refresh` — Refresh the index and report note/read-error counts.
  `info` — Inspect workspace and configuration.

New notes use YAML `id`, `aliases`, and `tags`. Daily notes retain both the
date ID and a human-readable date alias. Template IDs are replaced with the
created note's ID; existing daily notes are opened without modification.
Templates support `{{title}}`, `{{id}}`, `{{date}}`, `{{time}}`, plus
`templates.substitutions` values or functions receiving
`{title,id,time,vault}`. Unknown placeholders are retained. Use `template(name)` to insert a configured template into the current note.

SHARED LINKS AND COMPLETION *obsidian-tools-reference-shared-links-and-completion*

Inject the optional handler into markdown-tools; it does not import vault
code:

>lua
    require('markdown_tools').setup({
      link_handler = function(link, ctx)
        return require('obsidian_tools').follow_link(link, ctx)
      end,
    })
<

Outside a workspace, or for an external URI, this returns nil so the default
Markdown handler can continue. Inside a vault, note lookup considers explicit
paths, filename stems and IDs, then aliases. Duplicate matches open a picker.
Markdown links prefer the source note's directory; wiki links prefer the vault
root. Heading titles/slugs and `#^block-id` anchors are supported. Attachments
open through `vim.ui.open`; attachment preview/insertion belongs to
image-tools.

The completion-tools provider is `require('obsidian_tools.completion').new()`.
It exposes `trigger(ctx)` and `complete(ctx, callback)` with native LSP
CompletionItems. Select it in your completion-tools `sources` and configure
`trigger_characters` for wiki links/tags. It handles notes, aliases, headings,
block IDs and tags. Text edits consume existing closing `]]`, preserving pairs
ownership. It installs no Insert keys. Completion is disabled outside vaults,
inside excluded code/front matter, and in non-Insert contexts.

INDEX AND RENAME BEHAVIOR *obsidian-tools-reference-index-and-rename-behavior*

Index refreshes run in scheduled batches, coalesce concurrent callers, cache
unchanged documents by file stats and buffer ticks, and include unsaved
contents of existing note buffers for queries. Files removed or changed
externally are observed on the next refresh. `.git`, `.obsidian`, `.trash`,
`node_modules` and the template directory are excluded; symlink entries are
not traversed. The default per-note size limit is 4 MiB (`max_file_bytes`).
`ignore` customizes excluded names. `dispose()` invalidates queued work and
removes only unchanged owned commands. Invalid setup options leave the running
setup intact.

`plan_rename(destination)` returns a read-only proposal with
source/destination, before/after bytes for affected files and a reference
count. It writes nothing. `apply_rename(plan)` verifies file snapshots, clean
affected buffers, containment, symlink destinations and destination conflicts.
It stages replacements and backups, reserves the destination exclusively,
updates references, and rolls back reported write errors. Rollback failures
retain backup files and report paths. This multi-file operation is not
crash-atomic. Renames preserve original note IDs, aliases, link labels,
embeds, anchors, line endings and unrelated bytes. Moving a note adjusts its
resolved outgoing relative links, including attachments. Open unmodified
buffers are reloaded after the disk changes.

The shared lightweight Markdown parser supports single-line wiki/inline links,
reference links with single-line definitions, and ATX/Setext headings. Fenced
and indented code, inline code, front matter and HTML comments are excluded.
Multiline link labels/definitions, raw HTML/JSX, nested Obsidian heading paths
and general YAML features such as anchors/flow mappings are outside its syntax
coverage. Metadata extraction supports scalar IDs/titles and scalar/flow/block
lists for aliases/tags. Rename rewrites supported resolved references, leaves
unresolved references unchanged, and refuses ambiguous references involving
the moved note. It does not rename metadata IDs, headings or blocks, implement
graph views, Dataview, Canvas, Sync, or replace the Obsidian application.

DEVELOPMENT                             *obsidian-tools-reference-development*

>
    stylua --check lua tests
    OBSIDIAN_TOOLS_MARKDOWN_PATH=/path/to/markdown-tools.nvim \
      TMPDIR=/private/tmp nvim --clean --headless -i NONE -l tests/run.lua
<

The sibling `../markdown-tools.nvim` is the default test dependency. Tests use
a private temporary vault and cover link spans, metadata, anchors,
template/daily creation, completions, ambiguous matches, byte-preserving
rename/move, dirty and stale-file protection, exclusive destination
collisions, injected write failures, rollback, cancellation and setup/disposal
ownership.

Test workflow (tests/README.md): registered suites, filtering, required
fixtures and retained failure evidence.

OPTION DEFAULTS                                       *obsidian-tools-options*
                                                     *obsidian-tools-defaults*

workspaces: {name?: string, path: string}[] = {}. auto_detect: boolean =
false. notes_subdir: string = "notes". max_file_bytes: integer = 4 * 1024 *
1024. ignore: string[] = {".git", ".obsidian", ".trash", "node_modules"}.
note_id: function|false = false. daily_notes.folder = "dailies"; date_format =
"%Y-%m-%d"; alias_format = "%B %-d, %Y"; template = false; default_tags =
{"daily-notes"}. templates.folder = "templates"; date_format = "%Y-%m-%d";
time_format = "%H:%M"; substitutions = {}.

Workspace paths are expanded; nested workspaces select the longest match.
Folders must be vault-relative. setup() deep-merges supplied options with
fresh defaults and validates before replacing live state. Commands are
buffer-local inside selected vaults; inspection and setup do not scan notes.

COMMANDS
:ObsidianTools                 Searchable action menu
:ObsidianTools {action} [arg]   Invoke a workflow

Actions: quick_switch, new, daily, dailies, search, tags, backlinks,
follow_link, link, template, rename, refresh, info.

Commands are buffer-local to ordinary Markdown files inside configured vaults.
See the reference sections above for arguments, syntax coverage, completion
and template variables.

RENAME                                                  *obsidian-tools-rename*
rename takes a vault-relative path. Save the source and affected reference notes
first. plan_rename(path) prepares before/after byte snapshots without writing;
apply_rename(plan) validates snapshots and stages changes with error rollback.
Note IDs and aliases remain stable. Multi-file rename is not crash-atomic.

LIFECYCLE                                               *obsidian-tools-lifecycle*
                                                   *obsidian-tools-dispose*
setup() attaches existing/future Markdown buffers without scanning the vault.
dispose() removes owned commands and invalidates queued index/picker callbacks.
